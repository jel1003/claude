# 냉장고 셰프 🍳

냉장고에 있는 재료를 체크하면 **지금 만들 수 있는 메뉴**를 골라주고,
**매일 아침 그날의 식단**(아침·점심·저녁)을 자동으로 짜주는 웹앱입니다.

서버도 API 키도 없이 브라우저에서만 돌아갑니다. 데이터는 전부 `localStorage`에 남습니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm test         # 추천·식단 로직 테스트
npm run build    # 타입체크 + 프로덕션 빌드
```

## 기능

### 1. 재료 체크 → 메뉴 추천

재료를 눌러 체크하면 레시피 39개를 냉장고와 맞춰보고 추천 순으로 정렬합니다.

- **필수 / 선택 재료 구분** — 선택 재료(고명·부재료)가 없다고 메뉴가 빠지지 않습니다.
- **상비 양념 가정** — 소금·간장·참기름 등은 기본적으로 있다고 봅니다 (설정에서 끌 수 있음).
- **대체 재료** — 앞다리살 ↔ 삼겹살, 피망 ↔ 파프리카처럼 서로 대신할 수 있는 재료를 인정하고,
  무엇으로 대체했는지 표시합니다.
- **유통기한 임박 재료 우선** — 기한이 3일 이내로 남은 재료를 쓰는 메뉴에 가산점이 붙어 위로 올라옵니다.
  재료를 체크하면 재료별 기본 신선도로 기한이 자동 입력되고, 직접 고칠 수 있습니다.

정렬 기준은 `바로 가능 → 부족한 재료가 적은 것 → 점수 → 조리 시간이 짧은 것` 순입니다.
점수는 필수 재료 충족률 75% + 선택 재료 충족률 15% + 임박 재료 가산점(최대 15%)으로 냅니다.

각 메뉴 상태는 세 가지입니다.

| 상태 | 뜻 |
| --- | --- |
| `ready` | 필수 재료가 전부 있음 — 지금 바로 가능 |
| `almost` | 필수 재료가 1~2개 부족 — 조금만 사면 가능 |
| `lacking` | 그보다 더 부족 |

### 2. 매일 아침 자동 식단

설정한 시각(기본 07:00)이 지난 뒤 앱을 처음 열면 그날 식단이 자동으로 만들어집니다.

- **하루 동안 고정** — 날짜를 시드로 쓰는 결정적(deterministic) 난수라, 아침에 열든 저녁에 열든
  같은 날이면 같은 식단이 나옵니다. `다시 짜기`를 누르면 시드가 바뀌어 새로 뽑습니다.
- **만들 수 있는 것 우선** — 재료가 되는 메뉴가 하나라도 있으면 그 안에서만 고릅니다.
  하나도 없을 때만 '조금 부족한' 메뉴로 내려갑니다.
- **최근에 먹은 메뉴 회피** — 기본 3일(설정 가능). 하루 안에서 같은 메뉴가 두 번 나오지 않습니다.
- **끼니별 균형** — 아침은 20분·400kcal, 점심은 30분·600kcal, 저녁은 45분·650kcal을 기준으로
  맞고, 세 끼의 주재료(소/돼지/닭/해산물/계란/두부)와 조리법(볶음·국물·구이·무침…)이 겹치지 않게 뽑습니다.
- **밑반찬은 단독 배치 금지** — 시금치나물·오이무침 같은 반찬은 점심·저녁 한 끼로 세우지 않습니다.
- **장보기 목록** — 오늘 식단에 부족한 재료를 레시피별로 모아 보여줍니다.

### 3. 기기 간 동기화

폰과 PC에서 같은 냉장고를 보려면 **동기화 코드**(`ABCD-EFGH-2345` 꼴) 하나로 묶습니다.
한쪽에서 코드를 만들고 다른 기기에 넣으면 재료·식단·설정이 같이 움직입니다.

핵심은 **덮어쓰지 않고 합친다**는 점입니다. 서버는 올라온 문서를 저장된 문서와 병합해서
돌려주기 때문에, 폰에서 계란을 담는 동안 PC에서 두부를 담아도 한쪽이 사라지지 않습니다.

- **재료 단위 병합** — 재료 하나하나에 대해 마지막에 손댄 쪽이 이깁니다.
- **삭제도 기록으로 남깁니다**(tombstone). 그러지 않으면 한쪽에서 지운 재료가 다른 기기의
  오래된 목록에서 계속 되살아납니다. 삭제 기록은 30일 뒤 정리합니다.
- **식단**은 같은 날짜면 나중에 짠 쪽이, **설정**은 나중에 바꾼 쪽이 통째로 이깁니다.
- 병합 함수는 순서를 바꿔도(교환법칙) 여러 번 돌려도(멱등) 결과가 같아서, 클라이언트와
  서버가 각각 합쳐도 어긋나지 않습니다.
- 올리기와 내려받기가 **한 번의 왕복**입니다. 로컬이 바뀌면 1.2초 뒤, 그리고 60초마다 ·
  창이 다시 활성화될 때 같은 호출을 합니다.

저장소는 **Netlify Blobs**이고 엔드포인트는 `POST /api/sync` 하나입니다
(`netlify/functions/sync.mts`). 실제 처리는 `src/core/syncServer.ts`의 `handleSync`가 하며,
로컬 개발 서버(`vite.config.ts`의 `devSyncApi` 플러그인)도 저장소만 메모리로 바꿔 **같은 코드**를
돌립니다. 그래서 `npm run dev`만으로 Netlify 없이 동기화를 그대로 확인할 수 있습니다.

> **코드 관리**: 코드는 60비트라 남이 찍어 맞힐 값은 아니지만, **코드를 아는 사람은 그 냉장고를
> 볼 수 있습니다**. 로그인이 아니라 공유 비밀번호에 가깝습니다. 냉장고 재료 목록에는 이 정도가
> 적당하다고 보고 이렇게 했습니다. 계정이 필요하면 별도 인증을 붙여야 합니다.

> **알림에 대해**: 이 앱은 브라우저에서만 도는 앱이라 앱이 닫혀 있으면 알림을 보낼 수 없습니다.
> 설정의 브라우저 알림은 앱이 열려 있을 때만 뜹니다. 실제로 매일 아침 폰으로 알림을 받으려면
> 서버 크론 + Web Push(Service Worker)가 필요합니다 — 아래 '다음에 붙일 것' 참고.

## 배포 (Netlify)

`netlify.toml`에 빌드 설정이 들어 있어서, Netlify에서 이 저장소를 연결하면 그대로 빌드됩니다.

- 빌드 명령: `npm run build` / 배포 디렉터리: `dist` / Node 22
- SPA라 모든 경로를 `index.html`로 돌려주고, `/assets/*`는 파일명에 해시가 붙으므로 영구 캐시합니다.

Netlify 대시보드에서 **Add new project → Import an existing project → GitHub**로 이 저장소를 고르면
설정은 `netlify.toml`에서 자동으로 읽고, 이후에는 푸시할 때마다 자동 배포됩니다.

로컬에서 한 번만 올리려면:

```bash
npm run build
npx netlify deploy --prod --dir=dist
```

## 조향 상담 설문지 (`/perfume-survey/`)

냉장고 앱과 같은 사이트에 들어가는 별도 페이지입니다. Fragrantica 의 분류(향 계열 12종 · 메인 어코드 29종 ·
노트 12개 카테고리 · 계절/낮밤/지속력/확산력/성별 이미지 척도)로 취향을 묻고, 답할 때마다 대표 계열 ·
어코드 막대 · 탑/미들/베이스 노트 · 추천 부향률을 보여줍니다.

- **제출** — 고객이 개인정보 수집에 동의하고 `설문 제출하기`를 누르면 `POST /api/perfume-responses` 로
  저장되고 접수번호가 나옵니다. 저장소는 Netlify Blobs(`perfume-responses`)입니다.
- **서버에서 다시 정리** — 모르는 필드는 버리고 허용된 값만 남기며, 처방은 브라우저가 보낸 값을 믿지 않고
  서버가 다시 계산해서 요약과 함께 저장합니다. 숨은 입력칸으로 단순 스팸 봇을 걸러냅니다.
- **응답 확인** — `/perfume-survey/admin.html` 에서 관리자 키로 목록을 보고, 요약 복사 · CSV 내려받기를 할 수 있습니다.
- **실제 레시피 기록** — 응답을 펼치면 상담 후 실제로 만든 레시피를 시안별로 적을 수 있습니다
  (완성 중량 g · 부향률 중량 % · 재료별 방울 수와 g · 메모 · 최종본 표시).
  - **방울로 시안 테스트 → g 자동 변환**: 재료에 방울 수를 적으면 g 은 `방울 비율 × 향료 목표량(완성 중량 × 부향률)` 으로
    자동 계산됩니다(`gramsFromDrops`). 방울 · 중량 · 부향률 중 무엇을 바꿔도 g 이 바로 다시 계산됩니다.
    방울을 모두 지우면 g 을 직접 적을 수 있습니다.
  - **추천 비율로 먼저 채우기**: 시안을 추가하면 총 30방울을 탑 · 미들 · 베이스 추천 비율로 나눠(노트마다 최소 1방울)
    방울과 g 이 먼저 채워집니다(`suggestRecipe`). 부향률 기본값은 농도별 EDC 4 · EDT 10 · EDP 18 · Parfum 25%.
  - 저장하면 해당 응답에 붙어 서버에 남습니다(`PUT /api/perfume-responses?id=…`, 관리자 키 필요). CSV 에도 포함됩니다.

**관리자 키 설정**: Netlify 대시보드 → Project configuration → Environment variables 에서
`PERFUME_ADMIN_KEY` 를 길고 추측하기 어려운 값으로 추가하고 다시 배포하세요. 설정하지 않으면 제출은 되지만
목록 조회는 막혀 있습니다(503). 로컬 `npm run dev` 에서는 메모리 저장소를 쓰고 키 기본값은 `dev-admin` 입니다.

**설문 전용 사이트**: `scripts/stage-perfume-site.sh <폴더>` 로 설문만 담은 배포 폴더를 만들 수 있습니다.
그 폴더를 배포하면 설문이 사이트 루트(`/`)에, 응답함이 `/admin.html` 에 옵니다
(Netlify 프로젝트 `johyang-survey`).

```
public/perfume-survey/
  index.html      설문 화면
  admin.html      응답함 (관리자)
  engine.js       분류 데이터 · 점수 계산 · 처방 (브라우저와 서버가 같이 씀)
src/core/perfumeResponses.ts        제출 · 조회 처리, 답변 정리
netlify/functions/perfume-responses.mts   /api/perfume-responses (Netlify Blobs)
```

## 재료·레시피 추가하기

1. `src/data/ingredients.ts`에 재료를 추가합니다. `freshDays`를 적으면 체크할 때 유통기한이 자동으로 채워지고,
   `substitutes`를 적으면 대체 재료로 인정됩니다.
2. `src/data/recipes.ts`에 레시피를 추가합니다. 없어도 되는 재료는 `optional: true`,
   한 끼로 세우기 어려운 밑반찬은 `side: true`로 표시합니다.
3. `npm test` — `tests/data.test.ts`가 오타 난 재료 id, 중복 id, 빠진 조리 과정을 잡아줍니다.

## 다음에 붙일 것

- **로그인 기반 동기화**: 지금은 코드 공유 방식입니다. 계정이 필요하면 Netlify Identity 등을 붙이고
  `handleSync` 앞에 인증만 끼우면 됩니다.
- **진짜 아침 알림**: Service Worker + Web Push, 그리고 식단을 만들어 밀어주는 서버 크론.
  `generateDayPlan()`은 순수 함수라 서버에서 그대로 돌릴 수 있습니다.
- **재료 자동 차감**: 요리를 '만들었다'고 표시하면 쓴 재료를 냉장고에서 빼기.
- **주간 식단**: `generateDayPlan()`을 7일치 돌리고 장보기 목록을 한 번에 뽑기.
- **레시피 사진**, 알레르기·비건 필터, 인분 수 조절.
