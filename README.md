# 냉장고 셰프 🍳

냉장고에 있는 재료를 체크하면 **지금 만들 수 있는 메뉴**를 골라주고,
**매일 아침 그날의 식단**(아침·점심·저녁)을 자동으로 짜주는 웹앱입니다.

서버도 API 키도 없이 브라우저에서만 돌아갑니다. 데이터는 전부 `localStorage`에 남습니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm test         # 추천·식단 로직 테스트
npm run build    # 타입체크 + 프로덕션 빌드
```

## 기능

### 1. 재료 체크 → 메뉴 추천

재료를 눌러 체크하면 레시피 39개를 냉장고와 맞춰보고 추천 순으로 정렬합니다.

- **필수 / 선택 재료 구분** — 선택 재료(고명·부재료)가 없다고 메뉴가 빠지지 않습니다.
- **상비 양념 가정** — 소금·간장·참기름 등은 기본적으로 있다고 봅니다 (설정에서 끌 수 있음).
- **대체 재료** — 앞다리살 ↔ 삼겹살, 피망 ↔ 파프리카처럼 서로 대신할 수 있는 재료를 인정하고,
  무엇으로 대체했는지 표시합니다.
- **유통기한 임박 재료 우선** — 기한이 3일 이내로 남은 재료를 쓰는 메뉴에 가산점이 붙어 위로 올라옵니다.
  재료를 체크하면 재료별 기본 신선도로 기한이 자동 입력되고, 직접 고칠 수 있습니다.

정렬 기준은 `바로 가능 → 부족한 재료가 적은 것 → 점수 → 조리 시간이 짧은 것` 순입니다.
점수는 필수 재료 충족률 75% + 선택 재료 충족률 15% + 임박 재료 가산점(최대 15%)으로 냅니다.

각 메뉴 상태는 세 가지입니다.

| 상태 | 뜻 |
| --- | --- |
| `ready` | 필수 재료가 전부 있음 — 지금 바로 가능 |
| `almost` | 필수 재료가 1~2개 부족 — 조금만 사면 가능 |
| `lacking` | 그보다 더 부족 |

### 2. 매일 아침 자동 식단

설정한 시각(기본 07:00)이 지난 뒤 앱을 처음 열면 그날 식단이 자동으로 만들어집니다.

- **하루 동안 고정** — 날짜를 시드로 쓰는 결정적(deterministic) 난수라, 아침에 열든 저녁에 열든
  같은 날이면 같은 식단이 나옵니다. `다시 짜기`를 누르면 시드가 바뀌어 새로 뽑습니다.
- **만들 수 있는 것 우선** — 재료가 되는 메뉴가 하나라도 있으면 그 안에서만 고릅니다.
  하나도 없을 때만 '조금 부족한' 메뉴로 내려갑니다.
- **최근에 먹은 메뉴 회피** — 기본 3일(설정 가능). 하루 안에서 같은 메뉴가 두 번 나오지 않습니다.
- **끼니별 균형** — 아침은 20분·400kcal, 점심은 30분·600kcal, 저녁은 45분·650kcal을 기준으로
  맞고, 세 끼의 주재료(소/돼지/닭/해산물/계란/두부)와 조리법(볶음·국물·구이·무침…)이 겹치지 않게 뽑습니다.
- **밑반찬은 단독 배치 금지** — 시금치나물·오이무침 같은 반찬은 점심·저녁 한 끼로 세우지 않습니다.
- **장보기 목록** — 오늘 식단에 부족한 재료를 레시피별로 모아 보여줍니다.

> **알림에 대해**: 이 앱은 브라우저에서만 도는 앱이라 앱이 닫혀 있으면 알림을 보낼 수 없습니다.
> 설정의 브라우저 알림은 앱이 열려 있을 때만 뜹니다. 실제로 매일 아침 폰으로 알림을 받으려면
> 서버 크론 + Web Push(Service Worker)가 필요합니다 — 아래 '다음에 붙일 것' 참고.

## 구조

```
src/
  core/            로직 (React 의존 없음 — 전부 테스트 대상)
    types.ts       도메인 타입
    match.ts       재료 매칭 · 추천 점수 · 정렬
    planner.ts     하루 식단 편성 · 장보기 목록 · 요약
    rng.ts         시드 기반 난수 (같은 날짜 = 같은 식단)
    date.ts        YYYY-MM-DD 날짜 유틸
    storage.ts     localStorage 저장/복원
  data/
    ingredients.ts 재료 카탈로그 (80종, 카테고리·대체재·신선도)
    recipes.ts     레시피 DB (39종)
  components/      화면
  hooks/useDaily.ts 자정 감지 · 아침 자동 생성 트리거
tests/             vitest (44개)
```

## 배포 (Netlify)

`netlify.toml`에 빌드 설정이 들어 있어서, Netlify에서 이 저장소를 연결하면 그대로 빌드됩니다.

- 빌드 명령: `npm run build` / 배포 디렉터리: `dist` / Node 22
- SPA라 모든 경로를 `index.html`로 돌려주고, `/assets/*`는 파일명에 해시가 붙으므로 영구 캐시합니다.

Netlify 대시보드에서 **Add new project → Import an existing project → GitHub**로 이 저장소를 고르면
설정은 `netlify.toml`에서 자동으로 읽고, 이후에는 푸시할 때마다 자동 배포됩니다.

로컬에서 한 번만 올리려면:

```bash
npm run build
npx netlify deploy --prod --dir=dist
```

## 재료·레시피 추가하기

1. `src/data/ingredients.ts`에 재료를 추가합니다. `freshDays`를 적으면 체크할 때 유통기한이 자동으로 채워지고,
   `substitutes`를 적으면 대체 재료로 인정됩니다.
2. `src/data/recipes.ts`에 레시피를 추가합니다. 없어도 되는 재료는 `optional: true`,
   한 끼로 세우기 어려운 밑반찬은 `side: true`로 표시합니다.
3. `npm test` — `tests/data.test.ts`가 오타 난 재료 id, 중복 id, 빠진 조리 과정을 잡아줍니다.
